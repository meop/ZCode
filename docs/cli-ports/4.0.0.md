# CLI port: 3.18.2 to 4.0.0

This records the comparison and validation performed for `cli/v4.0.0`, including corrections found during the port.
It describes the released executable source, not later documentation-only commits. A retained commit is evidence of
patch coverage; behavioral acceptance also depends on the source review, regressions and runtime checks below.

Three new regressions pass, and Desktop reset/recovery regressions still pass. |

The final credential change was required to preserve the fork's existing behavior; carrying the earlier helper call
unchanged would have enabled upstream's new Desktop reset policy in the standalone CLI. The encrypted storage format
remains `enc:v2`; this port did not require another 3.17-to-3.18-style format migration.

Other concrete adaptations:

- **Compaction:** for a 1,000,000-token window with a 128,000-token output maximum, upstream now reserves 80,000
  output tokens and a 13,000-token buffer, giving a 907,000-token threshold. A configured 200,000-token ceiling
  still lowers that threshold to 200,000. Both upstream and fork regression cases were kept.
- **MCP ownership:** upstream owns configuration reload, trust and adapter lifetime. The fork supplies standalone
  official identity through that adapter's existing injection point; it does not restore the old startup-only
  enabled/disabled construction path.
- **Bash ownership:** the core handler retains shell selection, safety, timeout and background lifecycle. The fork's
  filesystem-port check only recovers a missing retained cwd before request preparation.

### Manual packaged runtime observations

- A Linux x64 executable used an isolated HOME and copies of existing credential/configuration files, with storage
  and cache redirected into the temporary profile. Explicit credential-secret environment overrides were removed.
  It selected the configured model, answered a real prompt and exited zero. Hash comparisons confirmed the original
  copied source files were unchanged. This was repeated on the final credential-policy correction.
- A separate fresh-profile PTY exercised `/help`, `/new`, `/exit` and terminal titles; the process exited zero via
  `/exit`. The PTY harness sent text and Enter as separate terminal input events.
- Temporary credential copies and PTY profiles were removed. The ad hoc harnesses and raw runtime transcripts were
  not checked in; these are recorded observations, not durable CI artifacts or an automated runtime suite.
  The checked-in CLI regression separately covers two fresh headless credential processes.

## Remaining limits

No fork feature was intentionally removed, absorbed by upstream, or deferred in this port. No further required
compatibility change was identified by the recorded audit and checks. This does not establish absence of latent bugs.

Local runtime validation was Linux x64. Other-platform runtime checks, a long authenticated memory soak, real
long-session/plugin stress, transcript paging and exhaustive upstream-feature acceptance were not performed.
The existing memory bounds and tests do not establish those broader properties. The release remains a candidate
until practical use supports promoting it.
